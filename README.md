# MD Exporter

本地运行的 Markdown → PDF 排版工具，专为包含中文、日文注音、HTML 居中标签的歌词和学习笔记设计。原始文档不被修改，文档内容在请求内存中处理，不写入服务端文档库。运行时不依赖 CDN 或云服务。

## 启动

需要 Node.js 20+，以及本机安装的 Chrome 或 Edge。Windows 会自动查找常见安装位置。已经安装依赖时，双击 `start.cmd` 即可启动，再手动访问 **http://127.0.0.1:3210**。启动脚本优先使用系统 Node，也可使用当前电脑已有的 Codex 配套 Node。保持启动窗口运行，按 Ctrl+C 停止服务。

首次安装依赖：

```powershell
cd D:\JLA\每周一曲\markdown_to_pdf
npm install
npm start
```

也支持 `pnpm install` / `pnpm start`。首次下载依赖需要联网；之后运行和导出均可离线。如果本机没有 Chrome / Edge，可运行 `npm run install:browser` 下载专用 Chromium，或用 `BROWSER_PATH` 指定浏览器可执行文件。使用无头浏览器仅作服务端 PDF 排版。

## 使用

1. 拖入或选择 UTF-8 的 `.md` / `.markdown` / `.txt` 文件，也可直接粘贴、编辑内容。
2. 如有图片引用，导入配套图片或资源文件夹。`/image/Masukatto.jpg` 优先匹配资源目录中的 `image/Masukatto.jpg`；也可直接导入同名的 `Masukatto.jpg`，在没有路径匹配时按唯一文件名匹配。多个路径同时匹配时会提示冲突，不随意选取。
3. 可另外点击“选择头图”导入图片。它会替换文首独立图片；原文没有文首图片时添加到顶部。“移除头图”可恢复原文图片。头图不会改写 Markdown 源码，导入新文档时会清空。
4. 分别选择“中文字体”和“日文字体（含注音）”。默认覆盖原文的内联字体；取消勾选可保留元素自身指定的内联字体。
5. 点击“检查缺字”。中文、日文分别使用对应字体检测，结果分开显示；系统回退字体也可能补齐缺字，但不保证完整覆盖。
6. 可在“页眉文字”中启用并编辑页眉，在“图片水印”中上传水印；拖动滑块或输入数字调整排版。
7. 调整字号、行距、注音大小、纸张、边距和页码，点击“导出 PDF”。

要复现《マスカット》成品，直接导入 `examples/masukatto.md`，保持默认参数（A4、字号 12、行距 2、边距 18、注音 50%）。程序随附该曲封面和日语社社徽，单独导入 MD 即可生成 5 页（4 页歌词 + 1 页词汇讲解），无需另外导入图片。现有 `../output/masukatto/masukatto.md` 也可直接导入。默认中文为微软雅黑、日文优先 Meiryo，页眉页脚使用幼圆和 Arial Rounded MT Bold；其他电脑缺少这些字体时会回退，分页可能略有变化。浏览器与 LaTeX 的字形间距会有细微差别。

## 添加或替换专辑封面

以下两种方式任选一种。“每周一曲”样式会把封面放在首页歌曲资料左侧；“普通 Markdown”样式会将其作为文首头图。

### 方式一：直接上传封面（推荐）

1. 先导入歌曲的 Markdown 文件。
2. 在页面左侧找到“独立头图”，点击“选择头图”。
3. 选择本机的专辑封面图片，等待预览更新，然后点击“导出 PDF”。无需修改 Markdown 或填写图片路径。
4. 更换封面时，再次点击“选择头图”选择另一张图片。点击“移除头图”可取消此次上传，恢复 Markdown 中原有的封面（原文无封面则移除）。

上传的头图优先于文首原有图片，不会改写 Markdown 源文件。导入另一份 Markdown 时会清空此头图，因此应先导入文档，再选择封面。

### 方式二：Markdown 图片引用 + 导入配套图片

1. 在 Markdown 的 YAML 信息块之后、歌曲标题及歌词之前，单独写一行图片引用，并在上下保留空行。例如封面文件名为 `koiiro-sora.jpg`：

   ```markdown
   ---
   title: "恋色空"
   type: lyrics
   ---

   ![专辑封面](/image/koiiro-sora.jpg)

   <center>

   ## 恋色空
   ```

2. 将 Markdown 导入程序后，在页面左侧“配套图片”中点击“添加图片”，选择本机的 `koiiro-sora.jpg`。仅在 Markdown 中写路径并不会自动读取本机图片，仍需执行此导入步骤。
3. 也可点击“资源文件夹”，选择包含 `image/koiiro-sora.jpg` 的上级文件夹，一次导入配套图片。
4. 确认预览显示封面后再导出。若提示“图片未提供”，核对引用与实际文件名（含大小写和扩展名）是否一致；多个同名图片引起冲突时，使用完整相对路径匹配，或清空配套图片后仅导入需要的文件。

支持 PNG、JPEG、WebP、GIF，单张不超过 12 MB，建议使用正方形专辑图。图片网址不会自动下载，需先保存到本机再导入。`masukatto.md` 引用的 `/image/Masukatto.jpg` 封面已随程序附带，无需额外上传；其他歌曲请按上述方式添加。

## 每周一曲主题

“纸张 → 排版样式”可选择自动识别、每周一曲、普通 Markdown。自动识别时，带有 `type: lyrics` 的 Markdown 套用“每周一曲”主题，其余使用原来的白底样式。主题使用与《マスカット》一致的米色纸面、竹席背景、红色青海波侧边、居中日中歌词、封面/歌曲资料首栏、鸟居社徽和唱片贴纸，以及每页的圆体页眉页脚。原有的字体、字号、行距、注音大小、纸张、边距、页码、自定义页眉、图片水印和缺字检查依然可用。

要得到完整的首页信息，Markdown 使用下列结构：文首的 `![专辑封面](...)` 放入封面位置，居中区域的 `## 歌曲名 - 歌手`、`#### 专辑：`、`#### 作曲：`、`#### 作词：`、`#### 编曲：` 自动提取为歌曲资料。可在 front matter 中填写 `weekly_url`，它会显示在每页页眉的“在线收听”位置；未填写时按 `slug` 或导入文件名推导，例如 `masukatto.md` 对应 `https://hitszjla.club/lyrics/masukatto/`。粘贴正文且未指定 slug 时使用日语社歌词目录链接。程序不联网校验歌曲网址。

后续 PDF 的日语社收听链接统一使用新版域名 `https://hitszjla.club`。即使旧 Markdown 的 `weekly_url` 或 `url` 仍填写原域名，导出时也会自动迁移到新域名，并保留歌曲路径。

每组歌词用一段加粗日文加下一段中文译文，尽量保持同页；以“词汇”开头的标题另起一页，编号列表中的加粗词条排为词汇讲解。主题不打印音频控件和网易云 / QQ 按钮，收听入口统一放在页眉。其他歌曲的封面仍需导入配套图片或使用“独立头图”。

每周一曲的“字号 12”代表模板基准比例（日文歌词 12.5 pt、中文译文 10.2 pt），修改后按比例缩放正文；行距和注音大小也相对模板调整。边距 18 对应模板正文左右 24 mm，调大边距会相应缩窄正文；顶部 29 mm、底部 23 mm 固定保留给主题页眉页脚。自定义页眉留白在此基础上增加。预览与导出均按所选字体实际测量分页，长篇词汇讲解可续页；内容过大无法放入一页时会提示调整参数。

```markdown
---
title: "マスカット - 平原綾香"
type: lyrics
weekly_url: "https://hitszjla.club/lyrics/masukatto/"
---

![专辑封面](/image/Masukatto.jpg)

<center>

## マスカット - 平原綾香
#### 专辑：LOVE
#### 作曲：玉置浩二
#### 作词：玉置浩二
#### 编曲：新田雄一

**つぶぞろいのブドウを**

那颗粒饱满的葡萄

</center>
```

歌词只为汉字添加 `<ruby>漢字<rt>かんじ</rt></ruby>` 注音。片假名和原本为平假名的词直接保留原文，不重复添加读音。

## 中文 / 日文自动识别

识别针对“日文原文加粗、下一段为中文译文、ruby 标注读音、文末有中文词汇讲解”的文档结构：

- 有假名或 ruby 的日文段落使用日文字体，ruby 及其 rt 读音也使用日文字体。
- 在 `type: lyrics` 文档或 `center` 容器中，整段加粗的原文即使只有汉字，也按日文处理；其后的普通中文译文使用中文字体。
- 中文词汇讲解保留中文主体，其中的 ruby、加粗日文词语、带假名的「日文引用」和假名片段单独使用日文字体。
- 代码保持等宽字体，不纳入这两种字体的缺字检测。

这是基于格式和字符的规则识别，不会调用云端模型。纯汉字、中日文无分隔混写或不符合示例格式的文本可能存在歧义。可用 `<p lang="ja">東京</p>`、`<span lang="ja">日文词语</span>` 或 `lang="zh-CN"` 手动指定；嵌套的显式语言标记优先生效。纯汉字词语的语言不会仅凭字形准确推断。

头图支持 PNG / JPEG / WebP / GIF，最多 12 MB，与配套图片共用总大小限制；以原比例完整显示，最大高度 60 mm，避免过高的图片挤占正文。

## 页眉与图片水印

- 自定义页眉：启用后在每页重复，可编辑多行文字、选择独立字体、调整字号（6–48 pt）、颜色、粗体、左 / 中 / 右对齐及水平 / 垂直位置。普通版未单独选字体时跟随中文字体；每周一曲默认使用圆体，单独选择字体后同时用于主题页眉页脚。每周一曲的固定歌曲页眉始终保留，自定义文字作为附加层，需调整位置避开原有内容。“检查缺字”也会检查启用的自定义页眉。
- 水印：支持上传、替换或移除 PNG / JPEG / WebP / GIF 图片，保留透明背景与原图比例。可设置水平位置、垂直位置、宽度和不透明度，并可一键居中。图片放在正文下方，在每页相同位置重复。
- 位置单位是毫米，以整张纸的左上角为原点。页眉坐标是文本框左上角，水印坐标是图片中心；页眉文本框从所设水平位置延伸到右页边距，文字在该宽度内对齐。
- 大小滑块与数字输入框同步。更换纸张后，位置和宽度的上限自动更新；可重新点击“将水印居中”。超出纸张的图片部分会裁切。
- 有页眉文字时，每页正文上边距默认在基础页边距之上增加 10 mm（默认 18 → 28 mm）。可用“正文上方额外留白”滑块或数字输入框设置为 0–40 mm。预览和 PDF 使用相同的上边距，左右及下边距不受影响；页眉关闭或文字为空时不增加留白。较大字号、多行或较低的页眉可按需增加留白。页码可以独立关闭，不影响页眉。
- 每周一曲预览展示全部纸页，每页都有背景、页眉、页脚和水印；普通版连续预览只显示首页的页眉和水印位置，最终 PDF 每页都会重复显示。页眉与水印作为本次会话的排版设置保留，导入另一份 Markdown 时仍可复用。

水印单张不超过 12 MB，与头图、配套图片共用总大小限制（建议合计不超过 22 MB）。页眉打印使用系统已安装字体；如果字体仅位于额外的 `FONT_DIR` 目录中，请先安装该字体后再用于页眉。

普通版水印使用整页 PDF 坐标绘制，每周一曲水印使用每页独立的图像层；均在每页（包含末页）重复，位于正文、封面和页眉下方，每周一曲水印在纸面背景上方。文字及链接保留；GIF 使用解码时的静态画面。

## 格式支持

- Markdown：标题、段落、粗体、斜体、列表、引用、代码、表格、链接、图片、删除线。
- HTML：`center`、`ruby`、`rt`、`rp`、`rb`、`rtc`、`br`、`div`、`span`、`sub`、`sup`、表格、`details` 等安全排版标签。
- 保留 HTML 中安全的居中、文字颜色、字号和字体样式；默认使用所选字体覆盖原文字体。
- YAML front matter 不作为正文打印；`title` 用于 PDF 标题及文件名。文档内容均视为数据，不执行文档内的指令或脚本。
- 浏览器原生的 ruby 排版，以及 PDF 文本选择、字体子集嵌入、自动分页、页码。
- 普通版预览是缩放后的连续文档，最终分页以 PDF 为准；每周一曲预览使用与导出相同的分页函数。长段落会续页，单个无法容纳的内容会提示缩小字号或边距；标题、加粗歌词段落尽量与下一段保持同页。
- 日文加粗歌词与紧随其后的中文译文采用成组间距：组内更紧凑，译文与下一句歌词之间留出更大的空白（包含注音区域），便于对应阅读。

HTML 是安全子集，脚本、事件、iframe、任意 CSS、外部样式表不执行。Markdown 按 markdown-it 的规则解析，示例中的 `center` 后需保留空行，以便其内 Markdown 正常解析。不支持数学公式、Mermaid 或站点主题样式自动还原。

PDF 无法播放音视频，相关元素显示文字提示。外部图片不会自动下载，需手动导入 PNG / JPEG / WebP / GIF；SVG 不在支持范围内。Markdown 应为 UTF-8，其他编码请先转换。单张图片最多 12 MB，图片合计建议不超过 22 MB；请求总上限 35 MB，正文最多 200 万字符。

## 字体来自哪台电脑

服务会扫描 **运行 Node 服务的电脑** 的系统字体及当前用户字体，支持 TTF / OTF / TTC / OTC / WOFF / WOFF2 中字体解析库可识别的字面。字体集合中的字面会分别列出，界面按字体家族归类，自动选择常规字重，并为 PDF 提供同家族粗体和斜体。不是所有旧字体或可变字体都能被排版引擎完整支持；有问题时更换字体。

Windows 默认扫描 `C:\Windows\Fonts` 和 `%LOCALAPPDATA%\Microsoft\Windows\Fonts`。每次打开或刷新页面都会重新扫描，安装新字体后也可直接点击“重新扫描”，无需重启服务。也可用 `FONT_DIR` 添加字体目录，多个目录用操作系统路径分隔符分隔（Windows 用分号）。

字体列表优先显示字体文件自带的中文名称（如“霞鹜文楷”“微软雅黑”“宋体”），日文字体显示本地日文名称（如“游ゴシック”“メイリオ”），并附上英文原名。列表分为中文、日文和其他字体，日文字体下拉框优先列出日文分组。搜索同时匹配中文、日文、英文、繁体别名和字体内部名称；例如“霞鹜”“霞鶩”“LXGW”均可找到霞鹜文楷。分组依据名称元数据，实际字符覆盖仍应使用“检查缺字”确认。字体没有本地名称时保留原名。

另一台电脑通过局域网访问服务时，字体列表仍来自服务主机；预览会通过服务加载这些字体。打印浏览器使用同一套字体配置。请按字体授权使用、分发或嵌入字体。

## 配置与局域网部署

默认只监听 `127.0.0.1:3210`。如需在可信局域网提供服务：

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '3210'
npm start
```

其他设备访问 `http://服务主机IP:3210`，并按需放行防火墙。此工具没有账户系统，服务会提供系统字体文件给访问者，因此仅用于本机或可信局域网。不要直接暴露到公网；如需公网服务，请自行在前面部署 HTTPS、认证及访问限制。

其他可选变量：`BROWSER_PATH`（Chrome / Edge / Chromium 可执行文件）、`FONT_DIR`（额外字体目录）。Linux 可安装 Chromium 与中日文字体包，或运行 `npm run install:browser`；浏览器的系统依赖需由管理员预先安装。

## 工程文件

- `src/`：服务、文档解析、字体扫描、每周一曲排版和 PDF 导出。
- `public/`：网页界面、样式和社徽资源。
- `examples/`：示例 Markdown 和配套专辑封面。
- `start.cmd`：Windows 启动脚本。
- `package.json`、`pnpm-lock.yaml`：依赖与运行配置。
- `node_modules/`：已安装的运行依赖。

导出的 PDF 由浏览器下载，保存位置由浏览器设置决定。

技术依据：[markdown-it](https://github.com/markdown-it/markdown-it)、[sanitize-html](https://github.com/apostrophecms/sanitize-html)、[Playwright PDF 接口](https://playwright.dev/docs/api/class-page#page-pdf)、[fontkit](https://github.com/foliojs/fontkit)。
